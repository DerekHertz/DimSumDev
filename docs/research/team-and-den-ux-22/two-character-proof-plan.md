## Recommended route

Use Meshy **only for bounded source-mesh exploration**, then simplify, fit and rig locally to the den's motion/identity interface. Start with two candidates per character, allow one extra candidate each only if needed, and judge their silhouettes at scene/portrait size before investing in cleanup. Broad matte forms, sturdy tails/antlers and a few large color blocks matter more than detailed generation. No realistic fur, dense scales, tiny whisker geometry or per-character lights.

Retain the existing body/portrait as a fallback. Reuse work/sit/walk/idle/wave contracts, paw/tool sockets where anatomical fit permits, Team actions, labels, identity bindings and portrait export conventions. Existing panda-specific vertex weighting is not a species-independent autorigger. Dragon tail weighting, contact poses, garment fit and head/crown envelopes are explicit work. Prefer the existing procedural motion vocabulary rather than buying animation clips by default.

## Frame-time and motion acceptance

Keep the existing **30 fps cap**. Compare before/after on this RTX 3060 Ti reference machine, same Windows Chrome version, build mode, 1440×900 viewport, DPR, camera, actor/visitor/meeting count, themes, motion preference and shadow settings. Use the checked-in measurement harness without skipped draws or software rendering.

- Before the proof, refresh the baseline after 03 and the actual full-window shell land. Run three matched repetitions per scenario before and after; use 10-second warm-up and at least 30-second samples for the acceptance verdict. The inventory's shorter samples establish a starting baseline, not a long-session stability certificate.
- No observed average-FPS regression beyond repeat-run noise; keep delivery near the existing cap. Do not use cap compliance alone as the pass criterion.
- GPU p95 and render/animation CPU p95 must not worsen by more than **5%** against the matched baseline median of repetitions. A GPU p95 below **16.7 ms** is the headroom target; a capped 30 fps readout does not prove it. A significant regression returns for simplification rather than relaxing the limit.
- Steady JS heap and estimated geometry/texture memory must not increase because of replacements; five repeated load/dispose cycles leave no growing actor, geometry, texture, timer or subscription counts. These browser/geometry metrics do not pretend to measure exact process RAM or driver VRAM.
- Demonstrate work, sitting, walk/trot, idle and wave with both variants, near/far/first-person views, meeting visitors and actual conservative envelopes. The dragon's tail/antlers/brush/book and red panda's tail/headphones cannot clip occupied places. Reduced motion preserves validated ownership/placement without ambient animation.
- Exact role/runtime/project/run bindings, source/tool anchoring, error/loading fallback, Talk/View work, focus/Escape, selection and camera behavior stay intact. Use 04's approved one-topic/one-side-sheet layout; do not implement or redesign the shell as part of asset work.
